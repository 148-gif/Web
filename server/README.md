# השרת הקיים על Node ו־MySQL ב־cPanel

לוח הניהול, עיצובו וה־API הקיימים נשמרים. ה־Worker משתמש בשכבת פעולות נתונים משותפת: ב־Cloudflare היא ממשיכה לעבוד עם D1, וב־Node היא משתמשת במתאמי MySQL. רכיבי ההפעלה והייבוא נבדקים בענן מול MySQL אמיתי. הצלחת בדיקות מקומיות אינה אישור שהנתונים או תשתית הפרסום הועברו לאחסון.

בלוחות הבקרה אומתו Node24.22.1 זמין לבחירה, MySQL8.4.11-cll-lve ו־cPanel138.0.19 על Linux x86_64. יעד הבדיקה הציבורי הוא `https://hichal.yoterberama.com/`, ושורש המסמכים שלו הוא `/home/yoterber/hichal.yoterberama.com`. API באותו מקור יכול להשתמש ב־`/cms-api`; יש לאמת ניתוב Passenger/cPanel לפני הפעלה. בדיקות המסד בענן רצות מול MySQL8.4.13 מבודד, ולא מול build האחסון עצמו.

## הפעלה והרשאות

`node server/start.mjs` טוען הגדרות מהסביבה, מאמת מסד וסכימה קיימים ורק אז פותח מאזין. הוא אינו יוצר טבלאות, מייבא נתונים או מפרסם אתר. `SIGTERM` ו־`SIGINT` סוגרים בקשות וחיבורי מסד. אין לשמור סודות במאגר או בקבצים הציבוריים.

נדרשות שלוש תיקיות נפרדות: `CMS_APP_ROOT` לקוד היישום, `CMS_MEDIA_ROOT` לאחסון מדיה פרטי קבוע בהרשאות0700, ו־`CMS_PUBLIC_ROOT` לשורש האתר. הנתיבים חייבים להיות מוחלטים וקנוניים, ללא symlinks. תיקיית המדיה אינה חלק מתיקיית קוד מתחלפת ואינה נחשפת ישירות דרך Apache.

| הגדרה | משמעות |
| --- | --- |
| `CMS_PUBLIC_ORIGIN` | מקור ה־API ב־HTTPS, למשל מקור אתר הבדיקה |
| `CMS_API_BASE_PATH` | למשל `/cms-api`; ריק עבור מארח API נפרד |
| `ALLOWED_ORIGIN` | מקור האתר המדויק, ללא נתיב |
| `REPO`, `BRANCH` | המאגר וענף התוכן; הפריסה הסופית תצא מהמסטר לאחר הכללת ההתאמות שנבדקו |
| `GOOGLE_CLIENT_ID`, `OWNERS` | מזהה Google ורשימת גיבובי SHA-256 של בעלי האתר; אין ברירת מחדל שמעניקה הרשאות |
| `GITHUB_TOKEN`, `SESSION_SECRET` | סודות בסביבה בלבד; סוד חתימה באורך32 בתים לפחות |
| `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD` | חיבור למסד היישום, פורט3306 כברירת מחדל |
| `MYSQL_SSL`, `MYSQL_SSL_CA` | מרחוק נדרש `verify`: אימות שרשרת התעודה וזהות שם השרת; אפשר לתת נתיב מוחלט לתעודת CA. נדרש שם DNS, לא IP מספרי |
| `PORT`, `CMS_BIND_HOST` | מאזין מקומי מאחורי proxy, ברירת מחדל127.0.0.1:3000; יש לאמת את שיטת ההפעלה של הספק |
| `CMS_TRUSTED_PROXY_IPS` | מערך JSON של כתובות proxy מדויקות שאומתו; ריק כברירת מחדל |
| `CMS_STAGING` | `true` כברירת מחדל: `X-Robots-Tag: noindex, nofollow` בתשובות API, מדיה ושגיאות |
| `CMS_PUBLISH_ENABLED` | `false` כברירת מחדל. `true` מאפשר פרסום Git, אך **אינו יוצר תהליך פרסום ל־cPanel** |
| `CMS_READ_ONLY` | חוסם שינויי תוכן; מאפשר כניסה וקריאה. כניסה עדיין כותבת מוני קצב ויומן, ולכן אין זו הקפאה מלאה לצילום מסד |

`CMS_LOCAL_DEVELOPMENT=true` מאפשר HTTP רק למקור loopback בבדיקות. חיבורי MySQL מקומיים יכולים לפעול ללא TLS; מרחוק אין אפשרות לבטל אימות. הדרייבר משתמש ב־`utf8mb4_bin` ב־handshake בגלל מגבלת מזהה collation בדרייבר; הטבלאות נשארות `utf8mb4_0900_bin` מסוג NO_PAD, וההשוואות הקריטיות מדויקות.

מגבלות המדיה, התרגום והקצב ניתנות להגדרה באותם שמות של ה־Worker. מתאם Workers AI ל־Node כבוי כברירת מחדל; הוא משתמש רק בחשבון ובמודל הקיימים, עם מפתח ייעודי, מכסות, זמן המתנה וגבולות תשובה. המילון המקומי עובד גם בלעדיו. הוראות ההפעלה והמגבלות ב־[docs/workers-ai-node.txt](../docs/workers-ai-node.txt); הבדיקות המקומיות אינן מאמתות הרשאות, זמינות או תמחור בחשבון החי.

## אחסון ונתונים

- `mysql-store.mjs`: פעולות מפורשות, נעילות וטרנזקציות, השוואת טיוטה מלאה ומכסות אטומיות. `ensureSchema()` בודק בלבד ואינו מריץ DDL.
- `mysql-kv.mjs` ו־`mysql-rate-limit.mjs`: ערכי עורכים ומוני קצב; עדכונים אטומיים מגינים על שינויי הרשאות ושמות מקבילים.
- `mysql-schema.sql`: סכימה מפורשת ליעד חדש וריק בלבד. טקסט המקור נשמר כטקסט; טבלאות נעילה מתאמות הקצאה בין משתמשים.
- `file-media.mjs`: מטא־נתונים ותוכן במיכל אחד באמצעות קובץ זמני ו־rename אטומי; תוספת4KiB לקובץ. הגשה דרך `/m/` ב־API עם טווחי בתים. R2 גולמי מיובא דרך `put`, לא בהעתקת הקובץ ישירות לתיקיית המיכלים.

לפני צילום ההעברה יש לבדוק את הסכימה החיה ולשמור בנפרד Git והיסטוריה, D1, KV וכל אובייקטי R2. רוב התוכן המפורסם הוא קובצי Git. טיוטות, יומן וזהויות עורכים הם מידע פרטי ואינם נכנסים למאגר או לחבילה הציבורית.

פורמט צילום v1:

```json
{
  "format": "heichal-cms-snapshot",
  "version": 1,
  "tables": {"drafts": [], "log": [], "media": [], "media_chunks": [], "ai_usage": []},
  "kv": {}
}
```

המערכים הריקים מציגים פורמט בלבד. בצילום אמיתי נדרשות כל עמודות המקור וכל הרשומות. `kv` כולל מחרוזות JSON מקוריות עבור המפתחות הקיימים מבין `people`, `editors`, `owner-names`. טבלאות או מפתחות לא מוכרים אינם מושמטים בשקט. `request_limits` זמני ומתחיל ריק במפורש. אפשר לצרף `git: {repo, branch, commit}`. צילום עקבי מחייב עצירת כתיבות מתואמת; המאמת אינו מוכיח שהיצוא היה עקבי.

## הכנה וייבוא

`npm run cms:preflight` בודק מקומית בלי להתחבר למסד או להציג סודות. קוד יציאה2 מציין דרישות חסרות. גם דוח ללא חסמים אינו קובע שהפריסה מוכנה.

`npm run cms:plan -- --input /private/snapshot.json` מאמת צילום ומציג ספירות וחסמים. `--out /private/new-plan-directory` שומר תוכנית וגיבובים בתיקייה פרטית חדשה מחוץ למאגר ולאתר. ברירת המחדל מגבילה קלט ל־64MiB. העלאות ומחיקות פעילות חוסמות מוכנות; אין למחוק אותן כדי לעקוף את החסם.

`node scripts/import-mysql-migration.mjs --input /private/snapshot.json` הוא dry-run ללא חיבור למסד. הדוח כולל גיבובי מקור וסכימה לעיון. ייבוא אמיתי מחייב במפורש את כל האפשרויות:

```sh
node scripts/import-mysql-migration.mjs \
  --input /private/snapshot.json \
  --apply --initialize-schema --isolated-target \
  --database NEW_EMPTY_DATABASE \
  --source-sha256 REVIEWED_SOURCE_HASH \
  --schema-sha256 REVIEWED_SCHEMA_HASH
```

המסד נבחר בדגל מפורש, לא אוטומטית מתוך `MYSQL_DATABASE`. יעד לא ריק, צילום חסום וגיבובים שונים נדחים. DDL של MySQL אינו חלק מטרנזקציית הנתונים: כשל ביצירת הסכימה משאיר יעד חלקי לבדיקה. כל השורות מיובאות בטרנזקציה אחת עם קריאה חוזרת והשוואת ערכים לפני commit. כשל בשורות מבצע rollback, אך אינו מוחק אוטומטית את הסכימה. הצלחת הייבוא אינה מאמתת קובצי R2, Google או פרסום אתר.

## חבילת בדיקה ל־cPanel

`scripts/package-cpanel.mjs` יוצר חבילה פרטית מקומית בלבד. נדרשים קומיט מלא השווה לראש הענף המקומי שנבחר, עץ נקי וקובץ גיבוי מפורש של `.htaccess` מהיעד. יש לבדוק בנפרד שהענפים המרוחקים לא התקדמו.

```sh
node scripts/package-cpanel.mjs \
  --commit FULL_COMMIT_SHA --source-branch yaakov \
  --out /private/new-release \
  --site-origin https://hichal.yoterberama.com \
  --api-url https://hichal.yoterberama.com/cms-api \
  --apache-baseline /private/htaccess.original
```

הכלי בונה snapshot של הקומיט בתיקייה זמנית, בודק קישורים וביקורת קישורים, ומגדיר רק בחבילה את ה־API וה־CSP. `admin/build.json` חייב לזהות את הקומיט המדויק. החבילה כוללת `public/`, `app/` ו־`manifest.json` שנכתב אחרון ומכיל גיבוב לכל קובץ. אין בה `.git`, `node_modules`, סודות או צילומי מסד. כלי preflight והייבוא נמצאים ב־`app/scripts/`. מתקינים תלויות ייצור מה־lockfile באמצעות `npm ci --omit=dev --ignore-scripts` בתיקיית היישום הפרטית, לא בשורש הציבורי.

חבילת ה־CLI היא staging: לכל HTML נוסף `noindex,nofollow`; `.htaccess` משמר את גיבוי הוראות האחסון ומוסיף כותרת לכל סוגי הקבצים, כולל PDF ומדיה. `robots.txt` מאפשר סריקה כדי שמנוע החיפוש יקרא noindex. אין שינוי לאינדוקס GitHub Pages. חובה לאמת שהכותרת נשלחת בשרת, כולל שגיאות והפניות; `<IfModule>` אינו מוכיח שהמודול פעיל.

בהעברה אין להחליף תיקייה שלמה במחיקה. יש לשמר `.well-known`, `cgi-bin`, `php.ini`, `.user.ini` והוראות PHP/Passenger. קובץ baseline ישן אינו מחליף בדיקה שה־`.htaccess` החי לא השתנה. האריזה אינה העלאה, DNS, הפעלה או החלפה אוטומטית של האתר.

## לפני החלפת האתר הפעיל

1. לאמת גיבוי מלא ושחזור של Git, `gh-pages` (ה־workflow משתמש ב־force_orphan), D1, KV, R2 וגרסת Worker פעילה.
2. לתרגל צילום אמיתי מול יעד MySQL חדש, לבדוק קריאה חוזרת וכל קובץ מדיה. קבצים זמניים והזמנות `receiving` מחייבים בירור לאחר קריסה; אין ניקוי עיוור לפי גיל.
3. לאמת ב־cPanel startup, ניתוב `/cms-api`, זמן העלאה, proxy אמין, TLS וקישוריות Google/GitHub. להגדיר את מקור Google המדויק.
4. לאמת noindex באתר הניסוי וב־API, ואז לבדוק כניסה, טיוטות, מדיה ושימור כתובות קיימות.
5. להגדיר ולבדוק את תהליך הפרסום החוזר לפני הפעלת `CMS_PUBLISH_ENABLED`: GitHub בונה תוצר מהמסטר, ו־Cron פרטי ב־cPanel מושך ומאמת אותו. היישום והפקודות מתועדים ב־[docs/cpanel-publication.txt](../docs/cpanel-publication.txt). הבנייה חסומה עד להפעלת משתנה המאגר, וה־runner מבצע dry-run כברירת מחדל. לא נוצר Cron או מפתח כחלק מהמימוש.
6. חבילת cPanel מגדירה ללוח מעקב אחר תהליך הפרסום שלה; הצלחה דורשת גם רשומת פריסה וגם סמן קומיט תואם באתר. תצורת GitHub Pages המקורית ממשיכה לעקוב אחר Pages. פרסום סטטי שומר את הגדרות האחסון, הנתונים והמדיה הפרטית; שינוי בקובצי השרת מחייב עדכון נפרד ומאושר.
7. מיזוג למסטר מפעיל גם את תהליכי GitHub Pages ו־Cloudflare הקיימים. מתאמים מיזוגים ופריסה ושומרים את המקורות והגיבויים במהלך המעבר.
